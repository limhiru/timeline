# Timeline for Android

Kotlin + Jetpack Compose로 만든 실제 GPS 경로 기록 앱입니다. Android 8.0(API 26) 이상에서 실행하며 compile/target SDK는 35입니다. 지도 API 키, 로그인, 서버 없이 실행할 수 있습니다.

## 폰 선택 화면과 자동 타임라인 (Preview 4)

- 처음 화면에서 **Clear / Tinted**를 체크하여 유리 느낌 메뉴의 투명도·강조 색을 고릅니다. 선택은 앱 재실행 후에도 유지됩니다. 이미지의 분위기를 Compose로 구현한 것으로 iOS Liquid Glass 엔진이나 실제 배경 굴절은 사용하지 않습니다.
- 미리보기 또는 하단의 **홈 아이콘**은 실제 일별 자동 타임라인을 엽니다. **운동 아이콘**은 기존 연속 GPS 기록·되돌아가기·워치 공유 화면, **설정 아이콘**은 선택 화면으로 이동합니다. 홈의 날짜 선택에서 이전 날짜를 볼 수 있습니다.
- 설정/홈의 **자동 타임라인**을 켜고 정확한 위치·알림 권한을 허용하세요. Android 10 이상에서는 신체 활동 권한도 요청합니다. 이 권한은 걸음 센서를 위한 것이며 거부해도 사용 가능한 다른 이동 센서로 대체합니다. 자동 수집은 사용자 동의 없이 켜지지 않습니다.
- 켤 때 한 번 위치를 확인한 뒤 기본 **30분** 간격입니다. 정지 주기에는 GPS를 최대 **45초** 켜서 추정 오차 20m 이하의 첫 신선한 좌표를 얻은 후 GPS 요청을 해제합니다. 못 얻으면 다음 30분 주기로 넘어가며 무한 재시도하지 않습니다.
- 저전력 significant-motion 트리거와 사용 가능한 걸음 감지 센서를 우선 사용합니다. 둘을 등록할 수 없으면 가속도 센서의 지속적인 변화로 이동을 감지합니다. 대체 감지는 배터리 소모가 더 크며 기기·절전 상태에 따라 잠금 화면에서 반응이 늦을 수 있습니다. 움직임을 감지하면 즉시 GPS를 요청하고 **10초** 간격으로 확인합니다. 신뢰 가능한 GPS 속도도 이동 시간을 연장할 수 있습니다. 마지막 이동 증거 이후 **2분**이 지나면 30분 주기로 돌아갑니다.
- 이동 중에는 기존 자이로·가속도 정지 판단과 GPS 평활화·점프 차단을 사용합니다. 센서가 없거나 불확실하면 좌표를 가상으로 만들지 않습니다. 자이로만으로 절대 위치 정확도를 보장하지 않습니다.
- 자동 기록은 `files/automatic-timeline/YYYY-MM-DD.json`에 날짜별로 원자적으로 저장됩니다. 장소명은 조회하지 않고 실제 시각·좌표·추정 오차를 표시합니다. 정지 체크포인트나 GPS 공백은 경로 선으로 연결하지 않습니다. 자동 기록과 운동 경로는 별도 저장되며 **30분 사이의 길은 복원할 수 없으므로 되돌아가기에는 운동 기록을 사용하세요.**
- 자동 기록은 위치 foreground service와 지속 알림을 사용합니다. 비정확 `AlarmManager.setAndAllowWhileIdle` 알람으로 주기를 확인하며 정확 알람·백그라운드 위치 권한은 요구하지 않습니다. **30분/10초는 요청 주기이지 실행 보장이 아닙니다.** Doze·제조사 절전·GPS 환경 때문에 늦어질 수 있습니다. 종료 스위치나 알림의 기록 종료로 GPS·센서·알람을 해제합니다. 강제 종료·재부팅·프로세스 종료 후 자동 재시작하지 않으며 다시 직접 켜야 합니다.
- 운동·복귀 안내의 폰 GPS 1초, 워치 GPS 2초, 폰→워치 위치 제공 2초 요청은 이 자동 기록 주기와 무관하게 유지됩니다. 자동 타임라인 자체가 워치로 동기화되는 기능은 아닙니다.

## 실행과 설치

1. Android Studio에서 이 `android` 폴더를 엽니다.
2. Gradle 동기화를 완료하고 `app`을 실행합니다. Android SDK 35와 JDK 17 이상이 필요합니다.
3. 위치 권한 요청에서 **정확한 위치**를 허용하고 기기 위치 서비스를 켭니다. 알림 권한은 기록 상태를 알림으로 확인하기 위해 요청하며 거부해도 기록을 시작할 수 있습니다.
4. `기록 시작` → `일시정지` / `재개` → `종료`를 사용할 수 있습니다.
5. `되돌아가기`는 새 GPS 신호를 받은 뒤 가장 가까운 저장 지점부터 이전 지점을 순서대로 안내합니다. 이미 지나온 길을 다시 따라가며 출발점 근처에 도달하면 안내를 종료합니다.
6. 상단의 `기록` 버튼으로 저장한 경로를 불러올 수 있습니다. 기록·안내가 진행 중일 때는 다른 기록을 선택할 수 없습니다.

```sh
./gradlew :app:assembleDebug :tracking:testDebugUnitTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## 연결된 워치에 폰 위치 제공

1. **같은 릴리즈의 휴대폰용·워치용 APK를 모두 업데이트**합니다. 두 앱은 같은 applicationId와 서명을 사용해야 합니다. 각자 다른 PC/CI 빌드의 Debug APK를 섞으면 서명이 달라 연결되지 않을 수 있습니다.
2. 폰과 워치를 페어링하고 직접 연결합니다(예: Bluetooth). 폰 위치를 본인 위치로 사용하므로 **폰도 함께 휴대해야 합니다.** 직접 연결은 폰과 워치의 좌표가 같다는 보장이 아닙니다. Google Play services / Wear OS Data Layer가 필요하며, GMS가 없거나 통신 API가 실패하면 워치는 자체 GPS를 사용합니다.
3. 폰 Timeline의 **운동 아이콘**을 누른 뒤 **워치에 위치 공유**를 켜고 정확한 위치 권한을 허용합니다. 공유 알림이 표시되며 폰에서 운동 기록을 시작할 필요는 없습니다. 폰의 화면이 꺼져도 사용자 시작 `location` foreground service가 위치를 제공할 수 있습니다. 공유 알림의 `공유 끄기`나 앱 스위치로 종료할 수 있습니다.
4. 워치에서 기록 또는 되돌아가기를 시작합니다. 워치는 직접 연결된 폰 앱에 2초 간격으로 GPS·정지 감지 값·보수적 속도를 요청합니다. 폰 값이 유효할 때는 워치 GPS와 정지 감지용 리스너를 해제합니다. **나침반 방향은 손목의 방향이므로 워치 센서를 유지합니다.**
5. 워치 기록 메뉴에서 `위치: 폰 GPS` / `위치: 워치 GPS`를 확인합니다. 폰 앱이 없거나 공유가 꺼졌거나, 연결이 끊기거나, 추정 오차가 20m를 넘거나, 값의 나이가 8초를 넘으면 워치 GPS로 전환합니다. 새 폰 값이 도착하면 다시 폰을 사용합니다. API 연결 감지는 최대 약 5초, 데이터 신선도 만료는 최대 8초 기준이며 첫 워치 GPS 고정에는 추가 시간이 필요할 수 있습니다.

폰 공유는 워치의 요청이 15초 이상 없으면 GPS·센서 리스너를 해제합니다. 공유 서비스와 알림은 유지해 다음 요청 때 다시 읽을 수 있으며, 워치 요청이 폰의 공유를 켜거나 백그라운드에서 새 위치 서비스를 몰래 시작하지는 않습니다. 프로세스 종료·강제 중지 후에는 폰 공유를 다시 켜야 합니다. [Android 백그라운드 위치 FGS 제한](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)을 따릅니다.

위치 전달은 버전이 있는 `MessageClient` 요청/응답으로 구현했습니다. 요청 토큰, 폰 세션·샘플 번호, 폰 내부에서 계산한 GPS 나이 + 워치의 왕복 시간으로 오래된 값·중복·역순 응답을 검사합니다. **서로 다른 기기의 wall/monotonic clock을 직접 비교하지 않습니다.** 저장된 `DataItem`을 실시간 위치로 재사용하지 않습니다. 폰과 워치 양쪽에서 `Node.isNearby`를 검사하므로 LTE/클라우드로만 연결된 멀리 떨어진 폰의 위치는 사용하지 않습니다. [Data Layer 보안·서명 조건](https://developer.android.com/training/wearables/data/overview), [직접 연결 여부](https://developers.google.com/android/reference/com/google/android/gms/wearable/Node#isNearby()).

위치 출처가 바뀌면 필터를 초기화하고 기록을 새 segment로 나눠 두 GPS의 오차 차이를 이동 거리나 경로 선으로 합산하지 않습니다. 각 기록 지점에 `source: DEVICE/PHONE`을 저장하며 이전 저장 파일도 읽을 수 있습니다. 거리·시간·페이스와 경로 저장은 **워치 자체 기록** 기준입니다. 이 기능은 실시간 위치 공급이며 두 기기의 기록 목록·운동 상태 전체 동기화는 아닙니다.

## 동작

- GPS를 절대 위치 기준으로 사용하고 정확도 가중 2차원 칼만 필터로 좌표 흔들림을 줄입니다. 첫 위치는 추정 오차 20m 이하를 기다리며 이후 30m 초과, 오래된 신호, 중복·역순 샘플, 비정상 좌표를 거부합니다. 정확도 여유를 고려해 12m/s를 넘는 큰 점프를 **현재 위치 표시·역순 안내에도 적용하기 전에** 거부합니다.
- 자이로와 선형 가속도를 10Hz로 읽어 두 센서가 4초 이상 조용하고 최근 1.5초 이내에 갱신됐을 때만 정지 증거로 사용합니다. 가까운 GPS 드리프트를 고정해 불필요한 기록·거리 누적을 억제하며, 정지 증거와 충돌하는 큰 이동은 즉시 반영하지 않습니다. 센서가 없거나 신뢰할 수 없으면 GPS 필터만 사용합니다. 선형 가속도 센서가 없으면 가속도계에서 중력을 저역통과 필터로 제거합니다.
- GPS 속도의 오차를 뺀 보수적인 속도가 0.6m/s를 넘으면 정지 보정을 해제합니다. GPS 정확도가 크게 좋아졌을 때도 초기 좌표를 보정할 수 있습니다. 자이로는 회전을 감지할 뿐 이동 거리를 측정하지 않으므로 가속도 이중 적분이나 임의의 보행 거리로 GPS 없는 좌표를 생성하지 않습니다.
- 20초 이상 유효 위치가 끊기면 두 개의 일관된 좋은 신호로 위치를 다시 잡습니다. 기록은 새 segment로 나누어 신호 공백을 직선이나 이동 거리로 채우지 않습니다. 일시정지 재개·새 기록·되돌아가기 전환 시 좌표 필터를 초기화합니다.
- GPS 기록은 사용자 버튼으로 시작하는 `location` foreground service에서 수행합니다. 화면 잠금 중에도 알림을 표시하며 계속 기록합니다. [Android 위치 서비스 규칙](https://developer.android.com/develop/background-work/services/fgs/service-types#location)을 적용했습니다.
- 일시정지 구간은 별도 segment로 나누어 거리 계산과 경로 선 연결에서 제외합니다. 재개 시 새 좌표를 기다립니다.
- 경과 시간은 monotonic clock으로 계산합니다. 파일은 앱 내부 `files/tracks.json`에 AtomicFile로 저장하며 저장 작업은 별도 직렬 I/O 스레드에서 수행합니다. 5초마다 체크포인트를 저장하고 종료·일시정지 때도 저장합니다.
- 프로세스가 종료되면 마지막 체크포인트는 기록 목록에서 불러올 수 있습니다. 기록을 자동 재시작하지 않으며 미저장된 마지막 몇 초는 잃을 수 있습니다.
- 저장 파일이 손상되면 오류를 알리고 원본을 덮어쓰지 않습니다.
- 나침반은 자이로·가속도·자기장 결합 회전 벡터와 자기 편각 보정으로 진북 방위를 구하고, 시간 기반 최단각 필터로 0/360도 경계의 흔들림을 줄입니다. 회전 벡터가 없으면 geomagnetic rotation vector로 대체하며 북쪽이 없는 game rotation vector는 사용하지 않습니다. 센서 신호가 없거나 신뢰도가 낮으면 방향을 표시하지 않습니다. GPS가 오래 끊기면 현재 위치 표시와 안내 거리를 갱신하지 않고 새 신호를 기다립니다.
- 화면 밖에서는 나침반 리스너만 해제합니다. 정지 판단용 자이로·가속도는 기록·안내 동안 유지하고 일시정지·종료 때 해제합니다. 휴대폰에는 GPS 추정 오차와 정지 보정 여부를, 워치 기록 메뉴에는 추정 오차와 센서 상태를 표시합니다. `약 N m`는 GPS 제공 추정치이지 실제 오차의 보장이 아닙니다.

필터링은 GPS의 **흔들림을 줄이는 처리**이지 건물 반사 등으로 생기는 지속적인 절대 위치 오차를 없애는 처리가 아닙니다. 실내·터널·고층 건물 사이에서 센서만으로 정확한 복귀 경로를 보장할 수 없습니다. 평활화로 좌표가 조금 늦게 따라가거나 짧은 구간 거리가 줄어들 수 있습니다. 워치에서 손목을 움직이며 제자리에 서 있으면 정지 판단을 하지 않을 수 있습니다. 나침반의 방향은 기기를 향한 방향이며 걸어가는 방향과 항상 같지 않습니다.

## 화면과 안내 범위

상단 GPS 경로, 이동 시간별 타임라인, 거리·시간·페이스, 기록 버튼과 되돌아가기 안내를 제공합니다. 경로 화면은 북쪽이 위인 **오프라인 GPS 궤적**입니다. 도로 지도 타일, 장소명 자동 조회, 도로 기반 좌·우회전 안내는 구현하지 않았습니다. 경로가 교차하거나 GPS가 흔들리면 가장 가까운 지점 선택이 모호할 수 있습니다. 일시정지한 구간에는 기록 좌표가 없어 그 사이의 실제 길을 복원할 수 없습니다.

실기기에서 GPS/나침반 정확도, 화면 잠금 중 연속 기록, 절전 모드, 권한 거부와 재허용, 프로세스 종료 후 복원을 확인해 주세요. 제조사별 배터리 관리에 따라 기록 서비스가 중단될 수 있습니다.

## 검증

폰 UI·자동 기록 재현 테스트는 `tests/phone_adaptive_smoke.py`에 있습니다. 디버그 APK가 설치된 **임시 폰 에뮬레이터(Android 13 이상, 720×1280, 가속도 센서 지원)**에서만 실행하세요. 앱 권한·UI 설정을 변경하고 GPS/센서 값을 주입합니다. 실제 2분 정지 시간을 기다리며 사용자 저장 파일을 지우지 않습니다.


휴대폰·워치 APK 빌드, Lint(오류 없음), 공유 로직 **59개 테스트**를 통과했습니다. 추가 12개 테스트는 30분 기본 주기, 이동 시 즉시 전환, 2분 유예, 취득 실패 후 대기, 가속도 지속성, 같은 좌표의 정지 체크포인트, 경로 공백·저장 호환을 검사합니다. 테스트는 기존 기록·저장·안내와 함께 정지 드리프트, noisy 보행 궤적, GPS 속도에 따른 정지 보정 해제, 정확도 개선, 센서 누락·오래된 데이터, 중력 제거, 큰 위치 점프의 안내 차단, GPS 공백, 날짜 변경선, 코너 보존을 검사합니다. 폰 연동 테스트는 프로토콜 검증, 요청 일치, 나이·왕복 시간, 중복·역순 응답, 폰 프로세스 재시작, 연결 끊김·재연결, 공유 lease, 출처 변경과 이전 파일 호환을 검사합니다. API 30 Wear OS 에뮬레이터에서 폰 미연결 시 자체 GPS 기록, 정지 감지, GPS 노이즈 8회 주입 중 기록 지점 유지, 자이로 움직임 후 기록 재개, 화면 밖 자이로·가속도 유지와 나침반 해제, 큰 GPS 점프 차단, 일시정지·재개를 확인했습니다. **실물 폰–갤럭시 워치의 Data Layer 페어링·위치 송수신은 아직 검증하지 않았습니다.** 주입 좌표 테스트가 실기기 정확도 개선을 증명하지는 않습니다. 실제 센서 정확도와 제조사별 화면 잠금 동작은 실기기 검증이 남아 있습니다.
